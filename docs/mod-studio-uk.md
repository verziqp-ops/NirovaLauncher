# Nirova Mod Studio — план реалізації

Цей документ фіксує цільову поведінку вкладки «Моди» та межі того, що реально підтримує Horizon 26.3. Це специфікація, а не твердження, що редактор уже реалізований.

## 1. Структура вкладки
Вкладка «Моди» має два головні режими:
- **Бібліотека** — знайти, встановити, оновити, увімкнути/вимкнути та видалити моди.
- **Студія** — створити власний мод, відкрити проєкт, редагувати блоки/предмети, перевірити й експортувати `.hmod`.
У бібліотеці залишити наявний Horizon Registry, а також сумісні джерела для тих типів контенту, які реально підтримуються. Java JAR не показувати як сумісні з нативною грою Nirova.

## 2. Майстер нового мода
Поля: назва, namespace (автоматично з назви, з можливістю змінити), автор, версія, опис, іконка. Після створення відкривається робочий простір із деревом контенту: предмети, блоки, рецепти, текстури та моделі, налаштування мода.
Кнопки: «Зберегти», «Перевірити», «Зібрати .hmod», «Відкрити папку», «Тестувати».

## 3. Предмети
Початковий режим — «На основі предмета»: користувач вибирає vanilla template, задає власну назву/id, текстуру/модель, максимальний стек, рідкість та підтримувані data components.
Для мечів/інструментів інтерфейс показує тільки властивості, які справді можна задати в API 26.3. Не вигадувати поле «урон» або «міцність», якщо ці характеристики не підтримуються компонентами предмета/ігровим кодом. Перед показом таких полів треба перевірити фактичну схему components і застосування їх у грі.

## 4. Блоки
Поля, які вже описані в Horizon content schema: базовий блок-шаблон; Hardness (час руйнування); Explosion resistance; Light (0–15); Requires tool; Friction; Map color; Sounds; Collision/outline shapes і state properties — у розширеному режимі.
Властивості відображати людською мовою з одиницями та підказками. Не плутати hardness блока з HP моба чи міцністю предмета.

## 5. 3D і текстури
Цільовий редактор:
- 3D viewport із орбітою, панорамуванням, zoom-in/zoom-out, скиданням камери та перемиканням перспективи;
- сітка/осі та світло для читабельності моделі;
- текстурний режим із піпеткою, палітрою, HEX/RGB, вибором кольору, пензлем, заливкою, гумкою, undo/redo;
- синхронізація текстури з 3D preview;
- імпорт PNG та експорт у структуру assets;
- для блоків — куб/shape preview; для предметів — preview моделі, яку фактично підтримує ресурсний формат гри.
Піпетка має брати колір з поточного полотна/текстури. Вибір кольору — з палітри або HEX. Не обіцяти довільне скульптування мешів, доки формат Horizon не має такого імпорту.

## 6. Перевірка та експорт
Перед збіркою: перевірити manifest, namespace та API; JSON і посилання на текстури/моделі; межі числових властивостей; показувати помилки з назвою файлу та полем; створювати .hmod штатним horizon-mod пакувальником; запропонувати запустити гру з dev-модом для тесту.
Нативні .hnmod не змішувати з простим конструктором: це окремий режим для Rust-розробників, із попередженням про виконання native code.

## 7. Етапи реалізації
1. Schema layer: типізовані моделі редактора, читання/запис .hmod, валідація через наявний horizon-mod.
2. Бібліотека/проєкти: вкладки «Бібліотека» і «Мої проєкти», створення/відкриття/видалення проєкту.
3. Редактор властивостей: форми для блоків та предметів лише з підтримуваними полями.
4. Texture painter: палітра, HEX/RGB, піпетка, пензель, заливка, undo/redo, PNG import/export.
5. 3D viewport: інтерактивна модель, камера, zoom, live texture preview.
6. Тестування: збірка .hmod, запуск Nirova з dev-модом, перевірка реальних предметів/блоків у світі.

## 8. Поточний стан репозиторію
У launcher/src/mods_page.rs уже є сторінка бібліотеки модів із пошуком, інсталяцією, оновленням, увімкненням/вимкненням та перевірками. У crates/horizon-mods/src/content.rs є schema для content mods, зокрема блоків, предметів та їх компонентів. У crates/cargo-horizon-mod/src/main.rs уже є команди new, build, run, check.
Окремого візуального Mod Studio, texture painter та повноцінного інтерактивного 3D viewport у launcher наразі не виявлено. Їх треба реалізувати; не можна вважати їх готовими лише через наявність .hmod.

## 9. Критерії готовності
- Користувач може створити блок і предмет без ручного редагування JSON/TOML.
- Піпетка й палітра змінюють PNG текстуру, а 3D preview показує ці зміни.
- Можна задати лише властивості, які дійсно застосовуються в Horizon 26.3.
- Експортований .hmod проходить штатний check.
- Гра запускається з цим модом, а предмет/блок видно і можна використати у світі.
- Якщо будь-який із цих пунктів не пройшов тест — UI показує конкретну помилку, а не «успіх».
