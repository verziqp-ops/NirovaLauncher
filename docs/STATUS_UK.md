# Nirova — стан проєкту

Останнє оновлення: 2026-11-05  
Поточна гілка: `nirova/performance-and-design-foundation`

Це знімок стану коду, а не обіцянка готовності. «Є» означає, що основу або функцію знайдено в репозиторії; це не означає, що всі сценарії перевірені на кожній ОС.

## Що вже є

### Лаунчер
- Rust/GPUI застосунок Nirova Launcher.
- Заявлена цільова версія клієнта — **26.3**; інші версії не заявлені як підтримувані.
- Пошук локальних ігрових файлів і ручний вибір сумісних файлів.
- Локальні offline-профілі та Microsoft sign-in у налаштованих сценаріях.
- Локальний вибір PNG-скінів і плащів для offline-профілів.

### Horizon Engine
- Rust workspace із клієнтом, сервером, світом, мережевими та іншими рушійними crate.
- Інтегрований сервер одиночної гри за замовчуванням працює на окремому потоці.
- Є worker-інфраструктура для streaming чанків і мешів.
- Є окремі модулі сутностей/істот, фізики, світу та контентних модифікацій.
- Є інфраструктура вимірювання продуктивності лаунчера. У цій гілці обмежено буфер історії UI frame-time до 30 000 зразків.

### Дизайн і збірки
- Є спільний файл палітри лаунчера; у робочій гілці оновлена основа тем: темна — синьо-графітова з рожевим акцентом; світла — молочно-блакитна з рожевим акцентом.
- Макет Nirova використовується як орієнтир компонування, не як фінальний дизайн.
- `.github/workflows/launcher.yml` описує тести й збірку лаунчера для Windows, Linux, macOS Apple Silicon та Intel Mac, включно з Windows installer.
- `.github/workflows/game.yml` має окремий ручний pipeline для клієнта гри, який інтегрується у файли upstream Horizon Nightly. Це не standalone installer гри.

## Частково готове / треба перевірити
- Стабільність запуску на Windows, Linux і macOS — потрібні успішні CI та ручні smoke-тести.
- Пошук і підготовка локальних ігрових файлів — перевірити на чистій системі й різних шляхах.
- Microsoft sign-in, оновлення, збереження токенів і мережеві помилки — потрібні end-to-end перевірки.
- Єдина дизайн-система — палітра є, але треба пройти всі сторінки, фокуси, помилки, стани кнопок і масштабування.
- Продуктивність гри — є окремі потоки та streaming, але немає опублікованих порівняльних вимірів FPS/tick time/RAM до і після.
- Backend має налаштування `minecraft_dir`; повний зручний GUI-сценарій вибору папки треба перевірити й довести до кінця.

## Що ще реалізувати

### Пріоритет 1 — продуктивність і стабільність
1. Додати immutable/versioned render snapshots між серверною симуляцією та рендером.
2. Профілювати frame time, tick time, p95/p99, RAM, генерацію чанків і збереження світу.
3. Знайти блокування render thread та прибрати синхронний I/O з нього.
4. Обмежити черги, кеші й тимчасові буфери; повторно використовувати пам'ять там, де це безпечно.
5. Паралелити лише безпечні обчислення AI/physics після replay/golden-тестів; мутації світу застосовувати у стабільному порядку.
6. Зберегти семантику редстоуну, фізики, мобів, tick order і збережень.

### Пріоритет 2 — єдиний дизайн
1. Звести кольори, типографіку, відступи, радіуси, тіні й стани контролів до спільних tokens.
2. Переробити всі сторінки під одну систему.
3. Підібрати фінальний фон та арт-напрямок після затвердження палітри.
4. Перевірити контрастність, обидві теми, різні розміри вікна та масштабування.

### Пріоритет 3 — перед релізом
1. Успішно пройти CI/build для кожної цільової ОС.
2. Перевірити Windows installer на чистій Windows та архіви на Linux/macOS.
3. Налаштувати GitHub Actions secret `RELEASE_SIGNING_KEY`.
4. Перевірити підпис і SHA256 кожного артефакту.
5. Додати release notes, відомі обмеження та інструкцію першого запуску.
6. Створити реліз лише після успішної збірки та smoke-тестів.

## Завантаження зараз

**Публічного релізу з інсталяторами наразі немає.** На момент перевірки GitHub Releases порожній, а доступний список GitHub Actions runs не містив завершених збірок. Workflow лаунчера публікує реліз за тегом виду `launcher@1.2.3`, але вимагає налаштований секрет `RELEASE_SIGNING_KEY`.

Завантаження лаунчера й самої гри — різні речі. Лаунчер не містить Minecraft assets/jars; потрібні сумісні локальні ігрові файли. Не розповсюджувати їх без відповідних прав.

## Межі сумісності та безпеки
- Java Forge/Fabric/NeoForge моди не стають автоматично сумісними з Rust Horizon Engine; потрібен окремий стабільний SDK/API.
- Offline/guest-профіль не є способом обходити перевірку права запуску пропрієтарної Minecraft Java Edition.
- У базовій гілці знайдено `GATE_OPEN: bool = true` у `launcher/src/account.rs`. Це не додано цією гілкою; перед публічним розповсюдженням потрібен окремий security/legal review.
